# PapaBench-on-Ibex port and measurement harness (`papabench_ibex/`)

Status: FBW and Autopilot each run their **own upstream scheduler**, paced by the Ibex machine timer, on Verilator (standard Ibex + our SoC patches); the AVR peripherals are **modelled on real Ibex peripherals and interrupts** (TimerA/B/D/E, SPI master/slave, UART, GPIO, PWM) with deterministic stimuli from a simulation environment; `mcycle` is recorded per task activation and per upstream ISR call. Two ways to run: **single-MCU** (`make PROG=… run`: one program, the other MCU of the SPI link virtual) and **joint** (`make run-joint`: both programs at once on two Ibex SoCs linked by SPI). Open decisions are in `.claude/status.md` → To-do.

## Requirements (decided with the user)

- Two independent executables: `fbw.elf` and `autopilot.elf`, each with its own `main()`. `PAPABENCH_SINGLE` is never defined. A single-MCU run executes one program; the joint run (user, 2026-09-24) executes both at once, each on its own Ibex SoC (`hw/rtl/papabench_dual.sv`), linked by the real SPI. Single-MCU runs are kept.
- SPI link (user, 2026-09-24): on the Secure-Ibex SPI master (Autopilot) / slave (FBW); `SPDR` stays in software, no RTL change to the SPI.
- Target: standard Ibex (`sim_ibex`) on Verilator only. No Smtctx.
- ISA/ABI: `-march=rv32im -mabi=ilp32`; no libc, no heap; libgcc allowed (soft-float).
- Scheduler time base: HW timer `0x80000000` (IRQ 7); tick = AVR Timer2 period (16.384 ms) at 50 MHz = 819200 cycles (2026-09-23).
- Output: `mcycle` per task, tasks activated by the upstream scheduler (the earlier direct-call table mode was replaced, 2026-09-23).
- Sources in `bench/` are compiled unmodified; the only source change is a patch applied to a build-dir copy. Loop-bound and entry-point pragmas stay untouched.
- Real interrupts and peripherals (2026-09-23): upstream ISRs run from real Ibex interrupts; stimuli are deterministic (clock-driven, no host input); servos on the PWM; SoC hardware extended only through patches in `hw/patches/` (TimerC, 20-bit PWM, environment in the sim top).

## Architecture

Two sides that never include each other's headers (PapaBench `inttypes.h` makes `uint32_t` an `unsigned long`, newlib an `unsigned int`):

| Side | Files | Includes | Flags |
|---|---|---|---|
| PapaBench | upstream `.c` (instrumented), `harness/{fbw,autopilot}_glue.c`, `harness/periph.c`, `harness/{fbw,autopilot}_periph.c` | `include/` (our `sfr_defs.h`) first, then PapaBench | `PB_CFLAGS` (+ `INSTR_FLAGS` for upstream files) |
| Ibex | `harness/harness.c`, `harness/runtime.c`, `harness/calib.c`, Secure-Ibex `common/{reference_system_common,timer,uart}.c`, `hello_test/crt0.S` | Secure-Ibex `common/` | `IBEX_CFLAGS` |

They meet only through `harness/papabench_harness.h` (no fixed-width types): `papabench_tasks[]` (`{ name, first, last }`), `papabench_ntasks`, `papabench_prog_name[]`, `papabench_startup_ticks`, `papabench_check()`, `papabench_upstream_main()`, `papabench_calib()`, `papabench_tick_pending`, `papabench_tick_cycles`; the model interface `papabench_isrs[]`/`papabench_nisrs`, `papabench_isr_run()`, `papabench_periph_init()`, `papabench_periph_poll()`, `papabench_irqs[]`/`papabench_nirqs` (`{ irq, dispatch, enable }`: the Ibex interrupts the model owns). `harness/ibex_io.h` (SoC addresses, CSR helpers, `unsigned int` only) is included by both sides.

Build variants: `JOINT=1` (`-DPAPABENCH_JOINT=1` on both sides, `build/<prog>-joint[-nomeasure]/`) drops the virtual other MCU from the model and changes the end of run (below); `make run-joint` builds both programs that way and runs `Vpapabench_dual` in `build/joint[-nomeasure]/`.

Run flow (`harness.c` `main()`): `pcount_enable` → header line → `papabench_check()` → fill stats from the task table → 8 calls to `papabench_calib()` (hook overhead) and 8 `papabench_isr_run()` of an empty function (`isr_overhead`) → trap-cost measurement on the machine timer (IRQ 7; reported, not subtracted) → `papabench_periph_init()` (program model: event handlers, PWM, GPIO edge interrupt and environment enable on its own GPIO bank) → install the one wrapper `harness_irq` on every line of `papabench_irqs[]` (enable those with `enable = 1`; GPIO lines are enabled by the model) and on IRQ 7 with `harness_tick`, `mtimecmp = mtime + TICK_CYCLES`, enable IRQ 7 and `mstatus.MIE` → `papabench_upstream_main()` (never returns). The tick ISR, after `TICKS + papabench_startup_ticks` ticks, prints the report (the model's `link,` counters last, `papabench_periph_report()`) and calls `sim_halt()`; with `JOINT=1` it calls `papabench_periph_done()` instead (sets `gp_o[7]` of its bank) and returns: the program keeps running, serving the SPI link, and the dual top ends the simulation when both MCUs are done. The report is printed once (`harness_done`).

Linker script: `papabench_ibex/link.ld` (112 KiB code+data, 16 KiB stack = the whole 128 KiB RAM). The stock `link.ld` (56 KiB) no longer fits the Autopilot (58 KB text).

## Time base: Ibex timer → AVR Timer2 overflow

- Upstream schedulers call `timer_periodic()`, which tests `bit_is_set( TIFR, TOV2 )` and then writes `TIFR = 1 << TOV2` (AVR write-1-to-clear).
- `harness_timer_isr()` (`__attribute__((interrupt))`): `timecmp += TICK_CYCLES` (from the previous compare, so no drift), `timecmp_update()`, `papabench_tick_pending = 1`, count the tick, add its own body cycles to `harness_isr_cycles`.
- `include/arch/sfr_defs.h`: `bit_is_set( sfr, bit )` is `papabench_tick_take()` (test-and-clear of `papabench_tick_pending`, `runtime.c`) when `_SFR_ADDR( sfr ) == PAPABENCH_TIFR_ADDR && bit == PAPABENCH_TICK_BIT`, a plain memory test otherwise. The address test folds at compile time (verified in the FBW disassembly: one call to `papabench_tick_take`, inside the inlined `timer_periodic()`). The upstream "clear" write lands in `papabench_sfr[]` and is ignored.
- `PAPABENCH_TIFR_ADDR` comes from the Makefile (FBW ATmega8 `0x58`, Autopilot ATmega128 `0x56`), `PAPABENCH_TICK_BIT=6`; `papabench_check()` in the glue verifies both against the device header at run time.
- Resulting activation pattern over 61 ticks (verified): FBW runs `fbw_schedule()` once per tick (our patch; upstream looped it continuously, ~370 iterations per tick at `-Os`) → 60 activations per task, `servo_transmit` every 3 (19); Autopilot `periodic_task()` once per tick → navigation/altitude/climb every 15 ticks (4), `stabilisation_task`/`link_fbw_send` every 3 (20), reporting every 6 (10). The Autopilot first consumes 30 ticks in `mainloop.c`'s init wait (`papabench_startup_ticks`).

## Per-task measurement: selective `-finstrument-functions`

- Only the `first`/`last` function of each `PAPABENCH_TASK(...)` entry is instrumented. Makefile pipeline per program:
  1. `build/<prog>/plain/*.o`: PapaBench sources compiled with `-fkeep-inline-functions -fkeep-static-functions` (only for `nm`).
  2. `instrumented.txt`: `first`/`last` names parsed with `sed` from the `PAPABENCH_TASK( "name", first, last ),` lines of the glue file (one per line, this exact form).
  3. `functions.txt` (all `T`/`t` symbols of the plain objects) minus `instrumented.txt` → `exclude.txt`. The build fails if a task function is missing, or if an exclude entry is a substring of a task name (GCC's `-finstrument-functions-exclude-function-list` matches substrings).
  4. `build/<prog>/pb/*.o`: compiled with `-finstrument-functions -finstrument-functions-exclude-function-list=<exclude.txt>`; these are linked.
- Hooks (`harness.c`): `__cyg_profile_func_enter` finds the task whose `first` matches, stores it in `harness_open`, reads the start; `__cyg_profile_func_exit` reads the end first, then accepts only `fn == harness_open->last` (O(1), no search inside the window). Tasks never nest, so one open task is enough.
- `harness_now()` reads (`harness_isr_cycles`, `mcycle`) as a consistent pair (retry if the ISR fired between the reads); sample = Δmcycle − ΔISR-body cycles.
- `calib.c` is compiled with the same instrumentation; its minimum over 8 calls is printed as `overhead` (23 cycles at `-Os`) and is **included** in every sample.
- Composite Autopilot tasks: `navigation_task` = `estimator_propagate_state` … `course_run`, `reporting_task` = `send_boot` … `send_nav_ref`, `receive_gps_data_task` = `parse_gps_msg` … `send_takeOff`; the calls in between are not instrumented and are part of the sample.

## Peripheral models (`harness/periph.h`, `periph.c`, `{fbw,autopilot}_periph.c`)

**One peripheral, one function** (user, 2026-09-24): no Ibex peripheral serves two different functions across FBW and Autopilot, so the same map holds for a future joint run; a peripheral is shared only for the same function (TimerB = ADC, TimerC = SPI link). The map is in `harness/ibex_io.h`; each model lists its interrupts in `papabench_irqs[]` and touches nothing else. Servos only on the PWM (verified from `pwm.log`, `scripts/decode_pwm.py`); no program uses the Ibex UART TX.

The upstream code only touches `papabench_sfr[]`. A per-program model reads what it wrote there and drives the real SoC; AVR interrupt sources become Ibex interrupts; the upstream `SIGNAL()` handlers (`__vector_N`, plain C functions) are called from the Ibex handlers through `papabench_isr_run( id, fn )` (timed per ISR, `isr,...` lines).

| AVR source | FBW (`__vector_N`) | Autopilot (`__vector_N`) | Ibex resource |
|---|---|---|---|
| Timer2 overflow (tick) | — (polled) | — (polled) | machine timer, IRQ 7 (unchanged) |
| Timer1 compare A | servo, 6 | — | TimerA ch 0, IRQ 18 |
| Timer1 compare A | — | `link_fbw` byte pacing, 12 | TimerD ch 0, IRQ 22 (patch 0002) |
| ADC conversion complete | 14 | 21 | TimerB ch 0, IRQ 19 (13×128 AVR clocks = 5200 cycles) |
| SPI transfer complete | slave, 10 | — | SPI slave RX not empty, IRQ 21 |
| SPI transfer complete | — | master, 17 | SPI master RX not empty, IRQ 20 |
| UART TX complete | 13 (boot string, `servo_transmit`) | — (unused) | TimerE ch 0, IRQ 23 (patch 0002); virtual UART, bytes dropped |
| Timer1 input capture (radio PPM) | 5 | — | env → GPIO bank 0 `gp_i[0]` falling edge, IRQ 17 (patch 0003) |
| INT4 (modem clock) | — | 5 | env → GPIO bank 1 `gp_i[0]` falling edge, IRQ 24 (patch 0003); data bit PORTD.6 → bank 1 `gp_o[1]` |
| UART1 RX (GPS) | — | 30 | env → `uart_rx` → real UART RX FIFO, IRQ 16 |
| Servo outputs (4017) | PWM ch 0–9 (width just added to OCR1A, 20 ms period), GPIO bank 0 `gp_o[1]` clock, `gp_o[2]` reset | — | PWM |

- **Event channels**: each of TimerA, B, D, E carries up to `PB_MAX_CH` one-shot channels; the compare is the earliest armed one; its IRQ runs every due channel in channel order, then reprograms (writing `mtimecmp` clears the sticky IRQ). The machine timer's `mtime` (read only) is the time base of all models (`pb_now()`); all timers count the same clock from reset.
- **Time**: AVR clock = 16 MHz (`CLOCK`), Ibex = 50 MHz: `avr = ibex * 8 / 25` (`pb_avr_of_ibex()`, 32-bit hardware division while mtime < 2^32), `PB_IBEX_OF_AVR()` rounds up.
- **Synchronisation points** (all deterministic): after every wrapper (`papabench_periph_poll()` at the end of each harness IRQ wrapper) and in the idle loop (`papabench_tick_take()`, called by `timer_periodic()` on every main-loop iteration of both programs, with `mstatus.MIE` cleared). A poll detects what the software wrote: `TIMSK.OCIE1A` + `OCR1A` → (re)arm TimerA (FBW) / TimerD (Autopilot); `ADCSR`'s ADEN+ADIE+ADSC → arm a conversion; `UCSRB.TXCIE` with the transmitter idle → a byte was written to `UDR` (FBW virtual UART: byte dropped, TX-complete armed on TimerE after one 38400-baud byte time); SPI (below); `TIMSK.TICIE1` (FBW) → enable/disable IRQ 17; `EIMSK.INT4` (Autopilot) → enable/disable IRQ 24.
- **Counters read by ISRs** (`TCNT1`, `TCNT2`, `ICR1`): only read inside ISRs (`timer_now()` is never called), so they are written just before each upstream ISR (`pb_avr_snapshot()`). `pb_oc_sync()` measures an `OCR1A` written by that ISR **from the snapshot**, not from the time of the poll: the model's own cycles are not AVR time. (Measuring from "now" broke `link_fbw`'s `OCR1A = TCNT1 + 200`: ~263 AVR clocks of model work had passed, the compare fell a full 16-bit wrap later, each SPI byte took 4 ms.)
- **`SPDR` double register → real SPI**: AVR `SPDR` is one address (write = transmit, read = last byte received); the Ibex SPI has `TXDATA`/`RXDATA`, and a C lvalue cannot tell a read from a write, so `SPDR` stays in software (user, 2026-09-24: no RTL change to the SPI). `sfr_defs.h` routes every access to `papabench_spdr_access()`, which returns a fresh slot (ring of `PB_SPDR_SLOTS` = 8) preloaded with `papabench_spdr_rx` and counts accesses (`papabench_spdr_accesses`). The model sets `papabench_spdr_rx` to the byte it pops from `RXDATA` before running the SPI ISR, and `pb_spdr_flush( &seen, last_is_read, spi_base )` pushes the written bytes into `TXDATA`, by the upstream access pattern (same in both programs): **outside interrupts `SPDR` is only written** (`spi_reset()`, `link_fbw_send()`); **an ISR that touches it reads it last** and writes it before (write + read, or read alone on a frame's last byte). So after an SPI ISR every access but the last is a write; at a sync point every access is a write. Writes made outside an ISR are flushed before the ISR runs (keeps TX order). A push appends where an AVR write replaces the pending byte, and the RTL has no TX flush: a byte written late (its transfer already started, the slave sent 0x00) would stay queued and shift every later byte and frame of the link for good. So a write that finds the TX FIFO not empty is dropped and counted (`pb_spdr_dropped`, `link,spdr_dropped`), as an AVR write collision: the frame fails its checksum once, the next is aligned again. Normally the FIFO holds at most the next byte (the upstream code writes one byte per transfer).
- **FBW = SPI slave** (`fbw_periph.c`): IRQ 21 (RX not empty) → pop → `__vector_10` (if SPE+SPIE) → flush. Sync: slave CTRL from SPCR (SPE → EN, CPOL/CPHA), IE = RX; `PINB.2` (`SpiIsSelected()`) = slave STATUS.BUSY (chip select, synchronised); FRAME_DONE counted and cleared; task-context writes (`spi_reset()`) flushed. Timing budget: the FBW ISR must push byte k+1 before the master starts it (≥ 200 AVR clocks = 625 cycles after byte k, the Autopilot's OCR1A delay); later → the slave sends 0x00 (underrun) and the frame fails its checksum. First frame: nothing queued before it (`spi_reset()` runs only after a frame), byte 0 goes out as 0x00, as on the AVR.
- **Autopilot = SPI master** (`autopilot_periph.c`): sync order CS (= `PORTB.0` low, slave 0 select; a release counts a frame), DIV (SPCR SPR1:0: fck/4,16,64,128 → `(div·25+15)/16 − 1`, fck/16 → 24 = 1 MHz), CTRL (SPE+MSTR → EN, CPOL/CPHA; IE = RX), then flush (the write in `link_fbw_send()` starts the frame). IRQ 20 (RX not empty) → pop → `SPSR.SPIF` → `__vector_17` (arms OCR1A = TCNT1 + 200 on TimerD) → SPIF cleared. TimerD event → flush pending writes → `__vector_12` → flush (write + read; last byte: read, SPI_STOP). Accesses with the SPI off are dropped (the last ISR's read).
- **Virtual other MCU (single-MCU runs only, `JOINT=0`)**: on the SoC's other SPI end, looped back on chip by the sim top, using the resources of the role it plays. FBW run: **virtual Autopilot** on the SPI master (DIV 24, CS by software) + TimerD (ch 0): a frame every 3 ticks from tick 1 (`link_fbw_send()` rate), one byte every `PB_IBEX_OF_AVR( 8·16 + 200 )` = 1025 cycles (transfer 425 + OCR1A delay), commands from `fbw_spi_frame()` (full throttle, roll sweep ±MAX_PPRZ/4 over 16 frames, pitch MAX_PPRZ/10, `STATUS_AUTO_OK`); pops the FBW's reply bytes and checks their checksum. Autopilot run: **virtual FBW** on the SPI slave, IRQ 21 (RX, FRAME_DONE): keeps the slave's TX FIFO filled ahead of the master (16 bytes queued, one more per byte received) with `ap_spi_frame()` (radio OK + averaged channels, mode stick MANUAL frames 0–1, AUTO1 2–3, AUTO2 from 4, full throttle); checks the Autopilot's frame checksum and length; FRAME_DONE → next frame.
- **Link counters** (`link,` lines): `frames` (FBW: chip-select releases seen by the slave; Autopilot: releases by the master), `frames_err` (upstream: FBW `to_mega128.nb_err`, Autopilot `link_fbw_nb_err`, frames received with a bad checksum), `spdr_dropped`, FBW `tx_underrun` (frames in which the slave sent 0x00 for lack of a queued byte; the first frame always, since `spi_reset()` only runs after a frame — its checksum still matches, FBW's `xor_out` starts at 0), and in single runs `virtual_frames`/`virtual_err` (frames checked by the virtual MCU).
- **Chip select from the pin direction**: the Autopilot model asserts CS only when `DDRB.0` is set and `PORTB.0` is low. `PORTB.0` is 0 from reset until `spi_init()`; without the `DDRB` test the model selected the slave at start-up, the release counted a frame, and the virtual FBW restarted with its FIFO full, shifting every later frame by 7 bytes while their XOR checksums still matched (fixed 2026-09-24). The virtual FBW also ignores a select without transfers.
- **Joint run window**: `run-joint` builds FBW with `TICKS` + 30 (`AP_STARTUP_TICKS`, the Autopilot's init wait), so both programs report at the same tick and their counters cover the same frames.
- **GPIO**: each program owns one bank and never touches the other (`papabench_gpio` = `IBEX_GPIO0` in `fbw_periph.c`, `IBEX_GPIO1` in `autopilot_periph.c`; bits in `periph.h`): `gp_o[0]` environment enable, `gp_o[7]` run over, `gp_i[0]` the input line. `papabench_periph_init()` calls `pb_gpio_init()` (IRQ_FALL and IRQ_EN on `gp_i[0]`) before the enable; the IRQ wrapper acknowledges first (`pb_gpi_ack()`: write 1 to IRQ_STATUS). The core line (17/24) follows the AVR enable bit (sync point above); an edge while it is off stays latched in IRQ_STATUS and is taken when it is enabled, like an AVR interrupt flag.
- **ADC samples**: FBW ch 3 = 629 (11.1 V), ch 6 = 281 (5 V); Autopilot IR1/IR2 = level attitude (402/512) + a ±20-count 2 s roll triangle.

### Simulation environment (`hw/rtl/papabench_env.sv`, patch 0005; also in `papabench_dual.sv`)

Instantiated in the Verilator tops (single-MCU: on both GPIO banks of the one SoC; dual top: on the FBW's bank 0 and the Autopilot's bank 1); ports per program (`fbw_gpo_i`/`fbw_gpi_o`, `ap_gpo_i`/`ap_gpi_o`) plus `uart_rx`, driven from the clock and from `papabench_stim.svh` (generated at `make sim`/`make sim-dual` by `hw/stimulus/gen_stimulus.py`). Each program enables its own stimuli in `papabench_periph_init()` with `gp_o[0]` of its bank (FBW: PPM; Autopilot: modem clock, GPS); a stimulus starts counting when enabled, both can run at once. It outputs plain lines on `gp_i[0]` of each bank (PPM line, low 300 µs from every edge; modem clock square wave), idle high until enabled: the edge latching and the interrupt are in the GPIO (patch 0003). FBW: PPM, 36 frames of 9 channels (25 ms frames, sync ≥ 8 ms), aligned with FBW's 10-frame mode averaging (`ppm.c` `AVERAGING_PERIOD`): frames 0–9 mode 1100 µs (MANUAL), throttle 1600 µs; 10–19 mode 1600 µs (FBW AUTO, Autopilot AUTO1), throttle 2100 µs; 20–35 mode 1900 µs (AUTO2), throttle 2100 µs (> `GAZ_THRESHOLD_TAKEOFF`); roll triangle 1300–1900 µs over 16 frames; after frame 35 replayed from frame 20 (`PB_PPM_LOOP`), so the radio stays in AUTO2 (2026-09-24; was 40 frames MANUAL/AUTO, cyclic). In the joint run this radio reaches the Autopilot through FBW and the SPI link. Autopilot: modem clock 4800 Hz; GPS epochs every 250 ms from 250 ms (120 epochs = 30 s, NAV-POSUTM + NAV-STATUS + NAV-VELNED, 94 bytes at 115200 baud, circle of 80 m at 15 m/s, 200 m, 3D fix). Changing the stimulus requires `make sim`.

## Invariants

- Nothing under `bench/` or `Secure-Ibex/` is written; all outputs go to `papabench_ibex/build/<prog>/`.
- Every PapaBench function that is not a task boundary must be excluded from instrumentation, otherwise its hooks add cycles inside task samples. The generated lists enforce this; do not hand-edit `exclude.txt`.
- Samples are raw: they include `overhead`. Every harness interrupt wrapper body (tick and the model's interrupts: model work + upstream ISR + poll) is added to `harness_isr_cycles` and subtracted; the trap entry/exit (register save/restore, `mret`) is not (user, 2026-09-24): subtracting the calibrated constant `trap_overhead` (~100 cycles) over-subtracted, giving negative samples and too-low minima, because the real cost depends on where the interrupt lands. `trap_overhead` is still measured (`harness_trap_calib()`) and printed, for reference only. With the ADC firing every 5200 cycles this touches many samples, raising `max`; `servo_transmit` is hit on every activation (in step with the virtual SPI frames every 3 ticks), so even its `min` contains interrupts.
- ISR samples (`isr,...`) time only the upstream `__vector_N` call (plus `isr_overhead`, printed); ISRs never nest.
- Upstream code calling `papabench_spdr_access()` (every SPDR access) pays that call inside its own sample (e.g. `link_fbw_send`).
- `libgcc.a` in the only available toolchain is rv32imc: soft-float helpers execute compressed instructions (open decision).
- Size: `papabench_ibex/link.ld` gives 112 KiB; FBW ~18.5 KB text, Autopilot ~58 KB text (the stock 56 KiB `link.ld` is too small since the models).

## Traps

- A model that triggers on an access counter must consume the accesses made while the peripheral is off, or a later sync point sees a stale access (the SPI master race above).
- A model that computes a compare from "now" after an ISR instead of from the counter snapshot the ISR read loses AVR time to model overhead (see Peripheral models).
- The idle poll runs inside `timer_periodic()`: a program that stops calling it (e.g. a long upstream loop outside the scheduler) also stops the models' idle synchronisation; interrupts still sync.
- `gp_o` belongs to the models (`pb_gpo_write/toggle`, shadow in `periph.c`): writing the bank's OUT elsewhere would change the environment enable or the done bit. A model that wrote the other program's bank would break the bank separation (the point of patch 0003).
- A model must only touch the peripherals of its own functions (map in `ibex_io.h`): another program's peripheral, even an idle one, breaks the one-peripheral-one-function rule. The virtual other MCU (single runs) is the one exception by design: it uses the peripherals of the role it plays (virtual Autopilot: SPI master + TimerD; virtual FBW: SPI slave), and is compiled out with `JOINT=1`.
- `SPDR` read/write classification relies on the upstream pattern (see Peripheral models): code that read `SPDR` outside an ISR, or wrote it after reading it inside one, would be misclassified (a read pushed as a write, or a write lost).
- The SPI slave with CPHA = 0 shifts out the head of its TX FIFO as soon as the master starts: a byte queued late goes out in the next transfer, and there is no TX flush to resynchronise; the FBW's frame check (`frames_err` on the Autopilot) shows it.
- Joint run: `sim_halt()` from either MCU stops both; the harness must use `papabench_periph_done()` there (`JOINT=1` does). A `JOINT=1` ELF on the single-MCU simulator never ends (no one reads `gp_o[7]` there): `make run` refuses it.

- Adding a Secure-Ibex header to a glue file, or a PapaBench header to `harness.c`/`runtime.c`/`calib.c`, breaks the build with conflicting `uint32_t` typedefs.
- A glue task entry split over several lines, or not in the `PAPABENCH_TASK( "name", first, last ),` form, is invisible to the Makefile: the table still compiles but the function gets no hooks and the task reports count 0.
- A new task whose `first` is also called outside the task sequence would open a window that the next `last` closes; check call sites before adding composite tasks.
- Headers with the same name exist in `autopilot/` and `fly_by_wire/` (`spi.h`, `uart.h`, `timer.h`): for the Autopilot, `-I autopilot` must precede `-I fly_by_wire`.
- Wall time: ~0.5–0.6 M simulated cycles/s, so the default FBW run (61 ticks, 50 M cycles) takes ~1.5 min and the Autopilot (91 ticks, 75 M cycles) ~2 min; the joint run simulates two cores at ~0.28 M cycles/s, ~4.5 min (264 s) for the default run. Use `TICK_CYCLES` smaller for quick checks (must stay above the per-tick work, a few thousand cycles).
